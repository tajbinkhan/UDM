**Release type:** patch

This release fixes a security problem that could let a malicious download server overwrite a file you already have. Please update.

## Changed

- If you remove a download from the list and later add its link again, UDM now saves a new file and no longer continues the partial file left behind. Downloads still in the list pause, resume and retry as before.
- A download whose name ends like one of UDM's own working files, such as `.udmpart`, is now saved with `_` at the end of its name.

## Fixed

- A malicious server could replace a file already in your download folder. If you accepted a download named like UDM's resume file and then a second download with the name of your file, UDM wrote the server's data into your copy. Now a new download never writes into a file that is already there: it takes a new name such as `file (1).iso`, asks you, or replaces the file only if Options says to overwrite. ([GHSA-84fm-g2x8-6q2v](https://github.com/tajbinkhan/UDM/security/advisories/GHSA-84fm-g2x8-6q2v))
