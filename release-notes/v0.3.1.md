**Release type:** patch

This release fixes problems found by running UIDM on Linux, a download that failed after fetching every byte, and test copies that interfered with the installed UIDM. Most of the work since 0.3.0 rebuilt UIDM's insides into layers, which changes nothing you see.

## Changed

- UIDM's three programs now log to `uidm-daemon.log`, `uidm-host.log` and `uidm-gui.log` in the data folder (`%LOCALAPPDATA%\UIDM` on Windows, `~/Library/Application Support/UIDM` on macOS, `~/.local/share/uidm` on Linux). On Windows the daemon's log used to grow without limit in `%TEMP%`; a log over 5 MB now moves to `.old`. Passwords in addresses are hidden, and cookies or passwords no longer appear in the messages about a damaged settings or saved-requests file. (307eb6e, 36f529b)
- The window reads the disk and the system (the proxy, wake timers, the grabber's projects, browsers) on background threads, so it no longer pauses while it waits. A second batch's question waits its turn instead of replacing one already on screen. (14d3a2f, 529ac2b, b37e250)

## Fixed

- Starting UIDM while its window was open opened a second window on the same downloads. It brings the open window forward now, as IDM does. (9790532)
- On macOS and Linux, every window or file viewer UIDM started stayed behind as a defunct process until UIDM quit. They are cleaned up now. (9790532)
- Links sent by the browser with addresses that cannot be downloaded, such as `javascript:` or `file:`, were added to the list and then failed with a technical error. They are refused now. (9790532)
- On macOS and Linux, a copy started with `UIDM_INSTANCE` pointed the browsers at its own programs, taking browser capture away from the installed UIDM. A named copy leaves the browsers alone now. (9790532)
- On Windows, a copy started with `UIDM_INSTANCE` changed the installed UIDM's notification name and icon. A named copy has notifications of its own now. (faf3b93)
- A download started while its save-as dialog was open, then saved into a new folder, could end Failed with "No such file or directory" after fetching every byte. The folder is made now and the download finishes. (d044a7a)
- On Linux, a relative `XDG_CONFIG_HOME` or `XDG_DATA_HOME` is used as given again, so no files moved. (f0ad808)
