**Release type:** minor

This release brings UIDM's window closer to IDM's, with a menu bar, toolbar, category tree and IDM's columns, and closes the gaps found in four audits of IDM 6.43. It also fixes security holes found in a code review.

## New

### The window
- A native menu bar, a toolbar, a category tree and a download table with IDM's columns. Every dialog opens as a window of its own and stays on screen.
- View > Font, tray icon styles, Help > Tutorials and a fuller About box.
- The referrer is kept apart from the parent web page, so the list can sort by either.
- A sound for "When a queue starts", next to the sounds for a finished download, a failed one and a finished queue.

### Starting downloads
- The command line takes IDM's switches: `uidm-gui /d URL [/p folder] [/f name] [/a] [/n] [/q]` and `uidm-gui /s` to start the main queue. With UIDM open, the switches go to that window. (#159)
- Batch downloads take IDM's asterisk form: one `*` in the address, filled from From to To with numbers or letters, padded to a wildcard size.
- The Download later picker can start the queue and add a new queue.
- A download can leave its queue without leaving the list.

### Browser capture
- "Capture in this tab" at the top of the toolbar popup turns capture off for one tab, and greys its icon. Held keys apply to any download, not only link clicks. Private windows can be allowed.
- Downloads are caught at their response headers, and UIDM gets the whole request: headers, redirects, size and type.
- Context menu items for the page or frame address, "cannot find links" and "cannot reach UIDM" messages, and link titles sent with a link.
- The video button shows on more players, including audio, object and embed elements, and each player gets its own streams.
- HDS (F4M) streams download, and Facebook, Instagram and Vimeo pages go to yt-dlp. YouTube videos download through yt-dlp too.
- "Download all links" also collects frames, script and onclick addresses, and images inside a selection.

### Queues and the site grabber
- Periodic synchronization re-checks finished files in a queue or a grabber project for changes.
- The Queues dialog has Browse, Start now, Stop and Help.
- Grabber filters add to the type lists and keep name masks such as `photo_*.jpg`.
- A grabber project can use a login page, relative subfolders and overwrite, and shows a downloaded count while it runs.
- The grabber asks to save a project, can add its files on close, and opens projects from any folder. Update all explores the pages again with their scripts run.
- A scheduled project stops its downloads at its stop time and can force programs to close.

### Options
- Add a browser by its program file, restart a browser, and see whether the extension is connected.
- Speed Limiter: turn it on at startup, a per-file default, and remember per-file limits on resume.
- Del as a force-capture key, separate context menu items for Chromium browsers and Firefox, a choice of the download window's first tab, and a setting that hides the queue panel on batch dialogs.

## Changed

- A saved site login is sent over plain http or FTP only when its new "Plain connections" box is ticked. Before, a login saved for an https site could be sent in the clear to http or FTP on the same host. Digest logins still work over http. (93f3217)
- A video file served under a playlist address shows as a file with its type and size, and addresses that are no stream leave the video menu. (630119b, 93cf8fe)
- A window newer than the running daemon says so and offers Restart daemon, instead of showing a parser error. (105a38e)

## Fixed

- Another extension could change UIDM's settings, including the virus scanner command, through the native host. The host now passes on only the requests UIDM's extension sends, and the browser side can change only the video button settings. (7e07b30)
- A queue's "Force processes to terminate" box was lost on save, so a queue that shut the computer down never forced programs closed. It is saved now. (#133, 01c26f1)
- A download that finished while its save-as dialog was answered was fetched again from the start. It is kept now. (fa8b78a)
- On macOS and Linux, two parts of UIDM starting at once could each make their own secret key, and logins sealed with the losing one could not be read again. Only one key is made now. (207ddd8)
- A daemon started from a Store app, such as the Store's Firefox, kept its files in that app's private copy of AppData, and later connections failed with "could not prove it is the UIDM daemon". (501ff1e)
- The daemon log filled with empty bytes when the window or host started a daemon, and yt-dlp could convert and delete an unrelated file with the same name. (be29b3e)
- Grabber types such as `tar.gz` matched any name ending in them, Browser Restart timed out on Chrome and Edge, and Columns Cancel undid more than the columns. (c71332d)
